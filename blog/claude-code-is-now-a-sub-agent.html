Claude Code Is Now a Sub-Agent

Between August 17 and August 20, four companies — DeepSeek, UiPath, Warp, and Cursor — shipped essentially the same feature. Each one released a layer that schedules Claude Code and Codex as interchangeable, replaceable workers. Not "integrates with." Not "supports." Schedules, the way an operating system schedules processes.

Four independent product teams didn't coordinate. They didn't need to. They all looked at the same stack, drew the same box around the same layer, and shipped it within 72 hours of each other.

That's what an inflection looks like in real time. And it means something uncomfortable for Anthropic and OpenAI: the products they positioned as the terminus of the developer workflow — the thing you open, the thing you talk to — just became somebody else's executor.

What Actually Shipped This Week

Start with DeepSeek, because it's the most aggressive. DeepSeek Harness — the agent workbench open-sourced on August 13 under MIT, which hit 30,000+ GitHub stars on day one and set the record for the fastest project ever to reach 20,000 — shipped two more releases in the same week. RC.7 landed on August 17. RC.8 landed late at night on August 19, two days later.

The headline feature of RC.8 is not the multimodal support or the concurrent web_search fan-out. It's this: Claude Code and Codex can now be installed as Profile Bundles and run as sub-agents inside a DeepSeek Harness workflow. Codex gets a non-interactive permission mode, so it can run unattended. It supports multiple named instances, so one task can run several Codex workers in parallel on different jobs. And a reportDelivery mechanism returns results to the parent task and wakes it up, so multi-agent collaboration no longer means idle-waiting on a blocked parent.

A day earlier, on August 19, UiPath announced Maestro Flow — a developer-first orchestration canvas where builders use "the coding agents they already rely on, including Claude Code, Cursor, GitHub Copilot, and Codex" to design, run, observe, and govern end-to-end business processes as a single artifact, directly from VS Code or UiPath Studio. UiPath's CPTO Raghu Malpani put the framing in one sentence: "Enterprises don't have an agent problem; they have an orchestration problem."

On August 18, Warp shipped Factories — an out-of-the-box "software factory" built on the standard phases of software development (triage, specification, implementation, review, verification), where any phase can be automated by whichever coding agent and harness you choose. The system, Warp is careful to say, works as well with Codex as with Claude Code. Warp's CEO told TechCrunch the approach automates "30 to 35%" of tasks on a weekly basis inside his company, a number he expects to rise as "the harness improves."

And in the same August 19 window, Cursor's changelog reworked its cloud agents around persistence: Subscriptions that wake agents on pull requests, Slack threads, and schedules; a /goal command that holds a long-lived objective like "fix all flaky tests and make CI green" across sessions; and subagents that now spin up on isolated VMs, each with a clean copy of the project. Agents automatically subscribe to PRs they open and drive them to green, fixing CI failures along the way.

Look at what all four have in common. In every case, the coding agent — Claude Code, Codex, Copilot — is the unit of work, not the product. The product is the thing that assigns work to it, watches it, and collects the result.

The Inversion Nobody Ordered

For two years, the central question of the agent stack was: which model should my harness run? Models competed on benchmark scores; harnesses competed on how well they extracted performance from models. That question produced the compatibility-list era, where new models ship with charts naming the six harnesses they've been post-trained against.

This week settled a different question, one layer up: which scheduler should my harness run inside? And the answer, from four directions at once, is: whatever scheduler gets there first — because the harnesses themselves have become the portable part.

Here's the mechanism, and it's simpler than anyone predicted. Claude Code and Codex are closed-source products, but they are closed-source CLI processes. A process can be spawned, fed stdin, run in a non-interactive permission mode, and harvested for results. You don't need Anthropic's permission to schedule their agent any more than you need Oracle's permission to schedule a database. The interface is public because it has to be — it's how the product is used at all.

DeepSeek understood this faster than anyone. RC.7 wired Codex and Claude Code sub-agent tasks into a unified Job Panel. RC.8 packaged them as ready-to-install Profile Bundles. That's not integration work; that's productization of your competitors' flagship agents as replaceable plugins inside your runtime. As one analysis of the release put it: Anthropic and OpenAI can't stop this trend since the interfaces are public, but their ecological niche — the ownership of the developer's working environment — is genuinely being eroded.

This is a delicate position for the closed labs. Every Claude Code instance running inside DeepSeek Harness is still Claude Code — still consuming Anthropic tokens, still generating Anthropic revenue. But the relationship has inverted. Anthropic is no longer selling the developer a place to work. It's selling compute to someone else's operating system.

Why the Scheduling Layer Wins the Environment

The strategic logic here is old and unforgiving: models are replaceable, agents are replaceable, the working environment is not. Once a team organizes its work inside a system — once its job definitions, permission policies, session history, and delivery flows live there — migrating away means re-encoding all of it. That's exactly the position DeepSeek is targeting, and exactly what UiPath is selling to enterprises that already trust its orchestration engine, and exactly what Warp is packaging for engineering orgs that want the factory without designing one.

Look at what the scheduling layer actually owns, because this is where the durable value is pooling:

  • Job definition and dispatch. DeepSeek's Job Panel treats every sub-agent — whatever its vendor — as a job with a lifecycle. Warp maps jobs onto canonical SDLC phases. UiPath maps them onto governed business processes. The agent doesn't know what process it's inside. It doesn't need to.
  • Isolation and provisioning. Cursor's subagent VMs give each worker "an isolated copy of the project with clean context in its own cloud environment." The scheduler decides what a sub-agent is allowed to see. That's a security boundary, and whoever owns it owns the trust model.
  • Events and wakefulness. Cursor's Subscriptions wake agents on PRs, Slack threads, and schedules. An agent that responds to events is a service; an agent that responds to prompts is a chatbot. The scheduler is what turns one into the other.
  • Goals and persistence. A /goal like "make CI green" that survives across sessions is state that lives in the scheduler, not the agent. DeepSeek's reportDelivery — child finishes, parent wakes — is the same idea at the multi-agent level.

None of these capabilities require a better model. All of them survive a better model. That's the tell. When the layer above your product can swap your product out without noticing, you don't own the workflow anymore — you own a supply contract.

The Contrarian Read

Most people still think the agent wars are a model war — that Anthropic and OpenAI are competing on benchmark scores and context windows, and whoever wins the capability race wins the developer. The events of this week suggest the decisive territory was never the model layer. It's the environment layer, and the closed labs are in the process of losing it while winning usage.

Consider the asymmetry. Anthropic and OpenAI spent years making Claude Code and Codex excellent standalone products — polished, opinionated, tightly bound to their own models. That tight binding was supposed to be the moat. Instead, it made them predictable: a Claude Code instance running under Codex's non-interactive permission mode, inside a DeepSeek Profile Bundle, dispatched by a Warp factory phase, is a well-behaved, well-characterized worker. The very qualities that made them great products make them great components.

There's an echo here of something every infrastructure engineer knows from the database era. Oracle lost the enterprise not when SQL Server got better, but when the orchestration and reporting layers above databases standardized, and "which database" became a line item. The scheduling layer is becoming that layer for agents. The MCP and A2A protocol work standardized how agents talk to tools and each other; this week's releases are standardizing something more commercially decisive — who owns the surface the human actually lives on.

And note what the scheduler doesn't need to be good at: writing code. DeepSeek's pitch isn't that Harness produces better patches than Claude Code. It's that running three Claude Codes, two Codexes, and a DeepSeek model — in parallel, on named instances, with results delivered to waiting parents — beats running one of anything. Coordination beats capability once capability is commoditized. It always has.

What to Do This Week

If you're an engineer or platform lead, this week's news is actionable right now:

  • Stop treating your coding agent as the seat of your workflow. Whichever agent you use, assume it will be replaceable within a quarter. Put your job definitions, permission policies, and process state in a layer you control — a scheduler, a factory config, an orchestration canvas — not in agent-specific settings that die with the agent.
  • Audit where your session logs live. The history of what your agents did — and why — is becoming the most valuable artifact in the stack. If it's trapped inside a vendor's product, that's your exposure. Export paths matter more than feature lists.
  • Run one heterogeneous experiment. Install DeepSeek Harness (MIT, free, runs offline), wire Claude Code or Codex in as a sub-agent, and give it a real multi-file task. The point isn't to adopt it — it's to feel how quickly the mental model shifts from "my agent" to "a worker I dispatch." That shift is coming to your org either way.
  • If you're building product on top of agents, build at the scheduling layer. Event subscriptions, isolated worker provisioning, goal persistence, delivery semantics. That's where four companies just independently placed their bets, and where the switching costs of the next five years are being created.

The deeper principle is the one I keep returning to in Harness Engineering: The Complete Guide to Agent-First Software Development: the durable parts of the agent stack are never the parts that think. They're the parts that decide what thinking is needed, deliver the results, and remember what happened. This week, four shipping schedules agreed.

Claude Code became a sub-agent. The question that matters now is who signs the parent's timesheet.
