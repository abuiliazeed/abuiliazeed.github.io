Agents Assume a Frozen World

67.35% to 24.79%. Same model, same task, same repository, same conversation, same reasoning setting. GPT-6 Astra — the strongest coding agent anyone has measured — loses 43 points, and the model never changed. Nothing about the task got harder. Exactly one thing happened: while the agent was working, the workspace moved underneath it.

That number comes from SWE-Shift, a benchmark published this week by a research team that asked a question every existing coding benchmark quietly avoids: what happens to an agent when the world doesn't hold still while it works? The answer, across 17 agent systems and 1,080 controlled continuation runs, is that the entire industry has been optimizing for an environment that does not exist.

Most people read agent failure stats and think "the model wasn't smart enough." This data says something else entirely. The model was plenty smart. The harness taught it to trust a world that had already stopped being true.

The Experiment Nobody Was Running

Every repository-level benchmark you've heard of — SWE-bench, its Verified and Pro descendants, the multilingual variants — shares one hidden assumption: once the agent starts, nothing changes. The repo is frozen at a commit. The dependencies are pinned. The task description is final. The agent works in a photograph.

Real development is a film. A teammate merges to your branch while you're mid-refactor. A dependency gets bumped. An API schema changes. A test suite goes flaky. The requirements in the ticket get edited after a call you weren't on. Professional software work is defined by change arriving mid-task — that's arguably what makes it professional work instead of a homework problem.

SWE-Shift's design is the cleanest experimental answer to this I've seen, because it isolates the change itself. The agent works on a real task from a real repository. At a scheduled checkpoint, the runner snapshots everything: workspace, controller state, available tools, the full conversation history. Then it restores that snapshot twice. The Clean continuation resumes normally. The Shifted continuation resumes into a workspace where one task-relevant change has just landed — a collaborator edit, an interface change, a revised goal, a piece of evidence that's now stale.

Because both continuations share an identical prior execution, the gap between them is caused by the change and nothing else. This is the agent version of a controlled trial, and it's the first one run at scale: 120 scenarios across 12 families of change, each triggered at nine positions from 10% to 90% through the task, across 17 systems. The systems span the whole market — GPT-6 Astra and GPT-5.6 Sol in the Codex app, Claude Opus 5 and Claude Fable 5.1 in Claude Code, both at max reasoning, plus thirteen open-weight systems from Kimi K3 and DeepSeek V4 down to a 27B Qwen, all served locally on 32 B300 GPUs under identical million-token budgets.

The changes are fair by construction. Every scenario is verified to be recoverable — a valid path to completion still exists after the change, using tools the agent can reach. And every change is discoverable: it shows up as a workspace diff, a delivered message, or a state the agent can query. Nobody is ambushing the agent with information it could never have found.

The Collapse

All 17 systems drop. Not most — all. The frontier falls hardest.

GPT-6 Astra goes from 67.35% clean success to 24.79% after a change, with paired success — both continuations succeeding from the same snapshot — at 20.34%. Claude Fable 5.1: 62.01% to 18.33%. Claude Opus 5: 53.76% to 16.09%. GPT-5.6 Sol: 46.22% to 12.56%.

The most useful number in the whole paper is the Conditional Retention Rate: of the successes an agent achieves in a clean world, what fraction survives a change? Astra retains 30.20%. Read that again — the best agent on the planet, running at maximum reasoning in its vendor's own flagship harness, keeps fewer than one in three of its wins when the workspace moves.

And capability doesn't predict retention. Kimi K2.6, a mid-tier open model with a clean score of 20.50%, retains 34.63% of its successes — more than Astra. DeepSeek V4 Pro posts higher paired success than Kimi K3 despite lower clean scores. Whatever makes an agent robust to change, it isn't the same thing that makes it score well on a frozen benchmark. We have been ranking agents on one axis while production runs on the other.

Then there are the zeros, and they're the real story.

  • Tool and session changes: a tool, authorization, schema, or session protocol changes after execution begins. Paired success is 0.00% for 17 of 17 systems.
  • Stale evidence: an observation the agent is relying on describes an earlier state of the world. 0.00% for 17 of 17 systems.
  • Runtime and resource changes: a process, lock, port, or cache changes mid-task. Zero for 16 of 17 — the sole survivor scored 0.60%.
  • Newly disclosed constraints: a hidden requirement becomes visible during the run. Zero for 13 of 17.

The strongest system ever measured scores exactly zero — not rarely, not occasionally, structurally — on the two failure classes that are most guaranteed to occur in production: interfaces changing and evidence going stale.

It's not uniform incompetence, which is what makes this interesting. When a user directly edits the code the agent is working on, Kimi K3 handles it 63.5% of the time — near its clean ceiling. When an indirect collaborator change lands, GPT-6 Astra recovers 57.3% of the time. Agents can absorb a visible diff. What they cannot absorb is anything that invalidates their assumptions without announcing itself as a diff: a tool that now behaves differently, an auth token that expired, a test result from before the change they're still treating as current.

Why the Zeros Are the Story

Tool changes and stale evidence are the two families every system fails. They're also the two families getting more common by the quarter.

The industry just spent two years wiring agents into everything through tool-calling protocols. Every integration point is now a mid-execution change vector: schemas drift, endpoints get versioned, sessions expire, a dependency publishes a patch. And the same week SWE-Shift landed, OpenAI shipped GPT-6.1 Terra — a model whose explicit pitch is high-volume computer use at $1 per million input tokens, reading invoices and entering them into accounting software all day. Agents are being positioned to live for hours inside live systems that other humans and other agents are modifying concurrently. Those environments don't freeze. Nobody has scheduled a snapshot for them.

Consider what the zero actually means. In the benchmark, the change is guaranteed to be discoverable through tools the agent already has. In production, nobody guarantees anything — the schema change lands silently, the teammate merges without pinging you, the token expires without a farewell message. If 17 out of 17 systems score zero when discovery is a solved problem, the real-world number isn't better. It's undefined, and undefined in this context means broken.

The Tests Stay Green While the Work Is Destroyed

Here's the part that should genuinely worry anyone running agents against real repositories. The benchmark's audit cases show agents failing in ways their own verification cannot see.

In one Django scenario, a collaborator adds an API that controls when migration operations can be combined. The agent correctly uses the API, then — while fixing the original issue — deletes it. All 39 of the original task's tests pass. The task is complete, the diff is clean, everything is green. The preservation check fails: a teammate's valid work has been silently removed, and the test suite has no way to know, because the test suite predates the change.

In a scikit-learn scenario, the agent restores its access to current task evidence — and then edits code without querying that source again. The original checks pass. But the required fresh observation is missing, and the patch exceeds its allowed scope. The agent's final claim of "done" was certified against evidence from a world that no longer existed.

This is the deep finding, and it goes well beyond coding agents: a passing test suite is a record of the past. It certifies the task as originally specified. It says nothing about work that arrived after the spec, requirements that changed, or evidence that went stale. Every verification loop that runs against saved state — cached test output, a transcript summary, a checklist the agent wrote for itself three hours ago — is certifying a snapshot, not the world.

You Can't Buy Your Way Out

The obvious objection: just give the agent more tokens to think, more room to re-plan. The team tested that. They scaled the post-change budget from 500,000 tokens per continuation to 16 million — a 32x range.

Doubling the budget helps a little at first: up to a 4x increase, each doubling adds 0.79 to 2.67 points. Beyond that, the curve goes flat. Quadrupling from 4x to 16x adds a total of 0.19 to 0.28 points. At 16 million tokens per continuation — an absurd budget, more than most teams spend on a feature — paired success is still between 7% and 12%.

Sixteen times the compute moves the number by less than a rounding error. And the frontier apps didn't outperform the 27B open models on retention by anything resembling their price gap. The failure isn't in the reasoning. It's structural: the harness hands the agent a context and implicitly promises that the context is the world. When that promise breaks, more thinking inside the same broken context is just more confident confusion.

What Actually Moves the Number

The most encouraging result in the paper is also the cheapest one. In diagnostic controls, the team modified what the agent gets after the fork. They added three things: a change notice — an explicit message that something changed; a read-only state refresh — letting the agent observe the current world; and a history reset — removing the pre-change dialogue so the agent doesn't carry forward assumptions from the old world.

Together they add 5.98 to 8.71 points of paired success. Individually, the history reset is the largest single gain in four of the five tested systems. Stop and appreciate that: the most effective intervention was deleting context. The agent's own transcript — the thing every harness fights to preserve, compress, and pipe back in — becomes a liability after a change, because it encodes a world that no longer exists.

Timing matters too, and not in the direction you'd guess. For the frontier systems, changes that land late in the run are far more destructive: GPT-6 Astra loses 20 points when the intervention arrives at 70–90% through the task versus 10–30%. Claude Fable loses 15. The more work exists before the change, the more there is to invalidate and the more poisoned context there is to reason over. A few small open models actually gain slightly when changes arrive late — probably because there's less accumulated context to betray them. Longer sessions aren't just expensive, as we saw with suspended-agent runtimes last week. They're fragile. Exposure to change compounds with every step.

Note the ceiling, though: even with all three fixes, paired success tops out around 11–18%. The interventions claw back a fraction of the collapse. Nobody has solved this. The gap between "agent that scores well on a frozen benchmark" and "agent that survives a normal Tuesday" remains wide open — which means it remains a place where engineering, not capital, is the differentiator.

What to Do This Week

If you run agents on real code, treat SWE-Shift as a free audit of your assumptions. Five things are worth doing immediately:

  1. Run one chaos test. Start an agent on a real task, and mid-run, push a conflicting commit to the branch or bump a dependency. Watch what it does. Most teams have never done this once, and the benchmark says the median outcome is silent breakage with green tests.
  2. Force re-observation before writes. Any external event — a merge, a deploy, a schema change — should invalidate the agent's context. Your harness should re-run status, re-read the diff, and re-check the evidence before the next edit, not trust the transcript.
  3. Build a change feed. Route merges, dependency bumps, and schema changes to running agents as explicit messages. The single cheapest intervention in the controls was telling the agent that something changed. In production, that's a webhook — infrastructure you can build in an afternoon.
  4. Verify preservation, not just the task. After a run, diff the workspace for work that vanished, not just tests that pass. The Django case passed 39 tests while deleting a colleague's API. If your CI can't catch that, your CI is certifying the past.
  5. Keep sessions short and resumable. Late changes hurt most, and long contexts carry the most stale assumptions. Checkpoint often, fork instead of continuing, and treat the checkpoint-and-replan loop as your default execution model — it's one of the core disciplines in my book, Harness Engineering: The Complete Guide to Agent-First Software Development, and this benchmark is the strongest evidence for it yet.

The Unfrozen World

Every benchmark that made coding agents look competent over the past two years froze the world on their behalf. That courtesy was never available in production, and it's getting less available by the day as merge volumes climb into the tens of thousands per day and agents are pointed at live systems for hours at a stretch.

The reflex in the industry will be to wait for the next model. The data says that's the wrong bet: retention doesn't track capability, sixteen times the budget buys nothing, and the single best fix measured so far costs zero tokens. The agents that survive the next few years won't be the smartest ones. They'll be the ones whose harnesses assume the world moves — and keep the agent honest about what it currently knows.

Your agent doesn't fail because the task was hard. It fails because Tuesday happened.
