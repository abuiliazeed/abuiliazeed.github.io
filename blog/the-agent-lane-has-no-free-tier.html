The Agent Lane Has No Free Tier

114 million free requests a day for traditional apps. Zero for scaled AI agents. And a 30-day legal expiration date on every vector embedding, memory index, and organizational graph your agent builds along the way.

Yesterday, November 24, Google made its managed Workspace MCP servers and Workspace CLI generally available across Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, and Tasks, alongside Google Cloud Agent Gateway, Model Armor screening, and the Workspace AI Tools Addendum. Under that contract, AI agents must stop calling traditional Workspace REST APIs directly. Technical enforcement begins February 1, 2027; scaled billing begins April 1, 2027.

Most people read yesterday's posts as a governance upgrade — DLP checks, human confirmations, and dedicated agent identities in the request path. That part is real and solves a genuine security failure. It also obscures the larger architectural move buried in the billing tables and legal definitions: Google just split the SaaS API surface into a human-app lane on REST and an agent lane on MCP, turned an open protocol into a request-one-metered tollbooth, and wrote AI Harness into binding Terms of Service with rules that collide head-on with modern RAG, memory, and evaluation stacks.

Why the Twenty-Year REST Contract Broke

Give Google its due first. In the Google Cloud launch post, Workspace Engineering VP Chandu Thota and GCP President Brad Calder published what agent traffic is doing to a platform serving 4 billion users and 13 million organizations:

  • Workspace APIs now handle more than 2.8 trillion calls a month.
  • Public Google Drive API traffic is more than 2.5× its 2022 volume.
  • API callers drive more than 18 billion Drive reads every day.

Traditional REST APIs assumed a valid OAuth token implied deterministic software moving at human pace. Autonomous agents invert that model. Give an agent broad Gmail and Drive scopes, slip a prompt injection into an incoming email or shared doc, and it can read confidential files, change sharing permissions, or send external mail at machine speed before any admin sees a log.

Google's technical fix puts four controls directly in the request path:

  • Mandatory agent identity: OAuth 2.0 clients calling Workspace MCP servers must enable Use this client for an AI-powered agent (is_agentic). MCP servers reject non-agent OAuth clients, forcing teams to separate agent and non-agent traffic.
  • Inline policy and prompt screening: Every MCP call runs through Workspace permissions, DLP rules, classification labels, and Model Armor prompt-injection screening, with audit logs and revocation in the Admin Console.
  • Native human-in-the-loop (HITL) gates: Drafts and summaries run autonomously; sending external emails, changing Drive sharing, or bulk edits require IT-governed user confirmation.
  • Protocol-level egress control on GCP: Cloud Agent Gateway fronts LLM, MCP, and A2A traffic, verifying Agent Identities against Agent Registry and enforcing IAM and default-deny outbound rules.

That mirrors where the whole ecosystem is heading — from Microsoft's Agent Registry locking down identity to Shopify auto-publishing agent permission files. Security now lives in the protocol boundary, and CISOs will endorse it.

Then engineering opens the quota and pricing docs — and sees what the new gate costs.

114 Million Free vs. Zero: Inside the Billing Table

Google launched two project-wide usage tiers on November 24: a free Standard Tier (no billing account) and a paid Scaled Tier (configured for the entire Google Cloud project, not per API or MCP server). Unit prices look identical across REST and MCP — four buckets from $0.10 to $0.50 per 1,000 successful (2xx) requests. The asymmetry sits in the daily no-charge allowance:

Service & Bucket REST Scaled Free MCP Scaled Free Price / 1K
Gmail Light (metadata, labels) 70,000,000 / day 0 / day $0.10
Gmail Medium (messages, drafts) 10,000,000 / day 0 / day $0.20
Gmail Premium (get_thread, search_threads) 1,000,000 / day 0 / day $0.50
Calendar Plus (all methods) 1,000,000 / day 0 / day $0.25
Drive Light (metadata, permissions) 20,000,000 / day 0 / day $0.10
Drive Medium (create, copy, update) 7,000,000 / day 0 / day $0.20
Drive Plus (search_files, list_recent_files) 4,000,000 / day 0 / day $0.25
Drive Premium (read_file_content, downloads) 1,000,000 / day 0 / day $0.50

Add up the REST column: 114 million free requests per day per billing account across those eight buckets, resetting at midnight Pacific Time. Better still, enterprises running internal REST tools can skip Scaled Tier altogether using Google's internal-use exception to raise per-project REST quotas for free.

Now compare the four traps built into the agent lane:

  1. The 5,000-to-zero cliff. Standard Tier caps every GA Workspace MCP server at 5,000 requests per day, per project, per product, with quota requests disabled. A 50-person team running agents against Gmail and Drive crosses 5,000 calls before lunch. Enrolling the Cloud project in Scaled Tier removes that free allowance completely: starting April 1, 2027, Gmail, Calendar, and Drive MCP calls are billed from the very first request.
  2. No internal-use escape hatch. Google's usage tiers guide states it flatly: “MCP server quotas aren't eligible for increases under the internal-use exception.” Your own internal agent reading your own paid Workspace domain pays from call one once it outgrows 5,000 daily calls.
  3. Agent-native reads sit in the priciest buckets — and multiply. search_threads, get_thread, read_file_content, and download_file_content sit in Premium ($0.50/1K); search_files, list_recent_files, and every Calendar tool sit in Plus ($0.25/1K). And composite MCP tools bill as multiple billing units when they fan out across underlying APIs — in the Calendar MCP quota table, a single delete_event carries a query cost of 10.
  4. Split volume-discount tracks. Programmatic monthly discounts (17% marginal from $20K–$50K, 30% from $50K–$100K, 70% from $100K–$165K, 40% flat above $165K) run on separate tracks for REST and MCP. High-volume REST integrations do nothing to discount your MCP bill.

Trying to dodge the toll by staying on REST fails on February 1, 2027: technical enforcement caps any AI agent calling Workspace REST APIs directly at Standard Tier quotas regardless of tier, while the addendum bans obfuscating agent classification. For two years, the industry pitched MCP as USB-C for AI. Yesterday showed what happens when the data owner hosts the MCP server: the interoperability standard becomes a clean, protocol-level billing meter.

“AI Harness” Just Entered the Terms of Service

Pricing changes unit economics; the Workspace AI Tools Addendum (last modified November 24, 2026) changes architecture. Google is the first hyperscaler to define the agent harness directly inside binding API Terms of Service:

“AI Harness” means the software layer that can deploy an AI Agent, invoke tools or APIs, or orchestrate tasks across one or more AI Agents.

In Harness Engineering: The Complete Guide to Agent-First Software Development, I treat the harness as an engineering layer; as of yesterday, it is also a regulated legal category. Clause 1 mandates that any access tool driven by an AI Agent, AI Harness, or AI model must use a Google MCP server. Then read how Google defines “Google Technical Information”:

Information related to the GWS Service(s) obtained or derived from access to or interaction with the GWS Access Point(s) (including vector embeddings, memory indexes, user profiles, organizational graphs, and findings) or from failure patterns established from calls to GWS Access Points.

Under Clauses 2(b)–2(f), any harness connected to Google Workspace may not:

  • Store any Google Technical Information for more than 30 days (2b) or process it outside active, user-authorized tasks (2c).
  • Retain user data or derived embeddings, memory indexes, or org graphs after disconnect or revocation (2d).
  • Scrape or systematically probe Workspace endpoints, MCP servers, skills, documentation, or outputs beyond an active task (2e).
  • Use user data or Google Technical Information — including failure patterns — for model training, fine-tuning, evaluation dataset building, or model distillation (2f).

Look at the collision that unfolded on the exact same day. On November 24, LangChain launched “The Agent Lake” — pitching SmithDB, LangSmith Engine (60M+ production traces analyzed), and SmithTune to convert recurring agent failure patterns into eval datasets and fine-tuned models. The same day at Ignite 2026, Microsoft Foundry previewed Agent Optimizer to mine conversations into reusable skills. Meanwhile, an entire wave of enterprise AI products — search copilots, persistent RAG platforms, agentic CRMs, and memory layers — built their core UX by syncing Drive and Gmail into long-lived vector stores and organizational graphs.

Clause 2 puts a legal wall straight through all three patterns. No persistent Drive vector index past 30 days. No durable org graph from Gmail metadata. No feeding Workspace traces or failure patterns into an eval set or LoRA fine-tune — even stripped of user text — because failure patterns established from calls to GWS Access Points are explicitly covered, with immediate suspension or termination under Clause 3.

The competitive asymmetry needs no conspiracy theory. Third-party harnesses get a 5,000-call Standard ceiling, zero free Scaled MCP allowance, a 30-day memory wipe, and a ban on trace-derived evals. Google's own Gemini agents run natively inside Workspace's boundary — which Google's blog explicitly notes returns “synthesized summaries within Workspace's boundary” rather than letting external harnesses own the index.

The Playbook Every System of Record Will Copy

Every major SaaS system of record — Microsoft 365, Salesforce, Slack, Atlassian, ServiceNow, Notion — faces the same two pressures: surging machine-speed read traffic and enterprise CISOs alarmed by over-scoped agent OAuth tokens. Underneath sits a deeper commercial fear: if third-party harnesses pull enterprise context over free REST APIs into external vector stores and memory lakes, the SaaS vendor gets demoted to dumb storage while the harness captures the workflow and the margin.

Google just handed enterprise SaaS a four-step blueprint that security teams will applaud:

  1. Ship first-party MCP servers and a governed CLI with real security controls: DLP, prompt-injection screening, audit logs, and HITL confirmations.
  2. Split identity at OAuth (is_agentic) so deterministic apps and autonomous agents never share a lane.
  3. Cap REST fallback and meter MCP from call one, removing internal-use exemptions so internal agents pay too.
  4. Fence derived context in an AI Tools Addendum with short memory TTLs and bans on trace-derived evals and fine-tuning.

That ends the default sync-and-index agent architecture — pull everything over free REST, embed it once, query cheaply forever — and replaces it with ephemeral, server-mediated retrieval. It also doubles the penalty for sloppy harnesses. In The Amnesia Tax, I covered Microsoft Research's finding that after five tasks in the same repo, 30% of agent tool calls repeat prior work. On free REST, repeated reads only inflate LLM tokens. When search_threads and read_file_content bill at $0.50/1K from request one and composite tools multiply calls, an amnesiac harness pays twice on every wasted turn.

What to Do Before February 1, 2027

You have nine weeks until Google's MCP mandate and Workspace AI Tools Addendum take effect on February 1, 2027, and four months before Scaled Tier MCP billing begins on April 1. Five moves belong on your roadmap now:

  1. Split agent traffic into dedicated Cloud projects and is_agentic OAuth clients now. Because Scaled Tier applies project-wide and strips free MCP allowances, never mix deterministic REST apps and AI agents in one Cloud project. Keep traditional apps in Standard or internal-use projects and isolate agents with hard budget alerts.
  2. Price April 1 in billing units, not raw tool calls. Turn on the new quotas dashboard and Cost Estimator, export CSVs with composite MCP multipliers applied, and model your hottest loops at $0.25/1K (Plus) and $0.50/1K (Premium) — knowing REST spend sits on a separate discount track.
  3. Kill repeat reads inside active sessions. Cache retrieved threads, files, and metadata in ephemeral, task-scoped memory for the duration of an active user-authorized run so agents stop re-fetching the same documents three times per task.
  4. Enforce Clause 2 across RAG, memory, and eval pipelines. Add automated 30-day TTLs and OAuth-revocation purge hooks to any Workspace-derived embeddings, memory indexes, or org graphs before February 1, and filter Workspace traces and failure patterns out of eval-dataset and fine-tuning pipelines.
  5. Build every SaaS connector for the two-lane model. Add per-connector call metering, short-TTL context isolation, and HITL confirmation hooks into your harness abstraction layer now — before the next system of record closes its REST lane on a 60-day clock.

The free REST API was the quiet subsidy behind the first wave of enterprise AI agents. Yesterday, Google ended that subsidy across 2.8 trillion monthly calls — using security governance as the rationale, MCP as the meter, and a 30-day contract clause as the moat. If your harness still assumes data access is free and derived memory is yours to keep, your architecture just picked up a February 1 expiration date.
