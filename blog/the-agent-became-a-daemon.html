The Agent Became a Daemon

Somewhere inside DeepSeek, there is a group chat where an engineer flags a bug. Nobody @-mentions the AI. Nobody opens a ticket. The message was written for humans — and the system reads it anyway, decides the report is probably real, spins up a background environment, tries to reproduce the defect, and starts looking for a fix. By the time anyone thinks to ask for help, the work is already underway.

That system is not a concept video. In an article published Saturday, DeepSeek's Harness team described an experimental "super-agent" architecture built to continuously monitor information, manage many tasks in parallel, and act with less human supervision — and said an internal version is already operating continuously inside the company. The notable word in that sentence is not "smarter." It's "continuously."

Almost every agent you can buy today is, architecturally, a function call. You invoke it, it runs, it returns, it dies. The interesting agents of 2027 will be processes. They will have uptime. The shift from the first kind to the second is the most under-discussed change happening in agent engineering right now — and this week, the entire stack underneath it shipped.

What DeepSeek Actually Said

The super-agent article is an architecture argument, and its premise is a claim about bottlenecks. DeepSeek's diagnosis, as reported by China Daily: as models get better at individual tasks, the constraint becomes human attention — users have to switch between conversations, keep track of progress, and issue the next instruction. The super-agent is designed to move that coordination into the system, so people focus on higher-level decisions and reviewing results instead of supervising every step.

Read that back. The lab that cratered inference pricing twice is now saying the scarce resource isn't compute. It's your day. For two years the industry has optimized capability per parameter and cost per task. DeepSeek is pointing at a different variable: how much of you each unit of work requires. A genius collaborator who only works while you watch is capped by your calendar. Remove the watching, and the cap moves.

To be clear about what this is not: DeepSeek stressed the architecture is an engineering exploration, not a shipping feature. There's no benchmark, no paper with component diagrams, no API. What there is — an internal system that notices an unaddressed message in a chat channel, reproduces the bug behind it, and starts triage on its own — is a working existence proof of a different trigger model. The agent's input stopped being a prompt. It became an event stream.

The Chat Metaphor Is the Ceiling

The request-response pattern is so baked into how we think about AI that we stopped noticing it's a design choice. The chat window implies: nothing happens until you speak. Every mainstream coding agent inherits this. Your Claude Code session begins when you type and ends when you close the terminal. Context is reconstructed each morning like a sales rep re-reading their own notes. Between your messages, the agent doesn't exist.

A daemon inverts every one of those assumptions. It runs whether or not you're there. Its inputs are events — a message in a channel, a failed build, an alert, a new PR — not utterances. It holds standing intentions, not just the current conversation. And crucially, its output isn't only an answer: it's initiated work, plus an escalation when the work crosses a line that needs a human.

This is different from the other attention story in the air. Anthropic's thousand-agent biology sweep attacked the cost of expert attention — machines doing the reading no specialist would ever finish. DeepSeek's super-agent attacks the cost of operator attention — machines doing the supervising no founder should be doing anyway. One displaces the reading load; the other displaces the watching load. Both are harness problems, and only the second one shows up in your calendar.

The Stack for Uptime Arrived This Week

If agents become daemons, the infrastructure requirements change shape, and the tell is that every major vendor just shipped a piece of it:

  • Stateful sessions went mainstream. Anthropic's Message Threads, launched in beta November 2, let an agent send the full conversation once and then reference it by ID — with median time-to-first-token dropping about 35% on requests carrying 500k to 1M tokens. That's a session primitive: conversation state that lives server-side, in encrypted memory, surviving between calls. It's built for loops that never start fresh.
  • Agent work started following humans across surfaces. GitHub's new Copilot cloud experience persists the session — code, context, and agent work — so a task started in the IDE continues on mobile, in the CLI, in Slack. The session outlives any single tool. That's daemon behavior grafted onto a chat product.
  • Deterministic hands showed up for non-deterministic watchers. AWS now exposes Step Functions to agents as tools through the Bedrock AgentCore Gateway over MCP — an agent can invoke a workflow that "runs each step exactly as you defined it." An always-on system that notices things needs exactly this: reliable, auditable actuators it can fire without improvising the procedure each time.
  • The economics of idling collapsed. OpenAI's GPT-6.1 Terra went generally available on Bedrock at $1 per million input tokens and $5 per million output — roughly half of Sol — with a 1.05M-token context and task completion AWS pegs at about three times faster than its predecessor. MiniMax's M3.1 Flash, released mid-October, cut the overall cost of agent tasks by 70% while nearly tripling inference speed.

Put those together and the shape of an always-on agent appears: persistent server-side memory, continuity across every surface you touch, deterministic tools for the actions that must not vary, and a price floor low enough that a process can run all day without a finance conversation.

One number in that list deserves a second look: Terra scores 50.3% on Terminal-Bench 4.0 — solidly behind frontier reasoning models. That's not a bug in the positioning; it's the design. The cheap model isn't supposed to finish your hardest task. It's supposed to notice. The architecture that falls out is the two-tier loop I've written about before, except it now runs around the clock: an inexpensive sentinel watching the event stream, deciding what's real, and handing off to an expensive specialist only when the stakes justify the spend. The sentinel's job is triage, and triage doesn't need to be brilliant. It needs to be awake.

The Training Loop Noticed First

Here's the part of this week's news that will matter more in eighteen months than it does now. Meituan released LongCat-2.5 on November 2 — a 1.6-trillion-parameter mixture-of-experts model with roughly 48 billion active per token and a 1M-token context, trained on domestically produced Chinese accelerators under 80GB of memory using W4A4 quantization. The parameter count is the boring part. The methodology is the news: Meituan says it "converts failures encountered by real agents into reproducible training tasks."

Think about what that means as a loop. Agents run continuously → they fail in real, messily-situated ways → those failures become curriculum → the next model generation is specifically better at the exact situations where deployed agents broke. An installed base of running agents stops being a cost center and becomes a data flywheel. The labs that operate daemons will train on failure distributions the labs that sell chat endpoints never see.

You can already see the trajectory in DeepSeek's own quiet update from October 17 — billed as "minor," yet Terminal-Bench 4.0 jumped from 31.2 to 42.3, and DeepSWE hit 77.0, ahead of Claude Opus 5 at 74.0. Kimi's K3.1 Pro ships with a 1M-token window explicitly pitched at long-horizon agent work. China Daily's framing — that China's AI race is moving "beyond model size and benchmark scores" toward whether AI can reliably turn intelligence into action — is not spin. It's an accurate description of where the release cadence actually is: every major Chinese lab this month shipped something whose headline feature is stamina, not IQ.

What Breaks When Agents Have Uptime

Before you start wiring a model into your Slack, sit with how the failure model changes. A chat agent fails visibly — you're watching when it goes wrong, and the blast radius is one conversation. A daemon fails silently, at 3 a.m., and the failure compounds until something downstream notices. Four things specifically:

Cost drift. A watcher that fires two thousand times a day is a new line item with a life of its own. Without per-trigger budgets and per-tier metering, your sentinel quietly becomes your biggest subscription.

Governance, not just capability. The DeepSeek system's most striking behavior — acting on a message not addressed to it — is precisely the behavior that needs a policy answer. Which channels can it read? Who consents to an AI ingesting messages written for humans? An ambient agent is a listening system with a work ethic, and "it was only trying to help" is not a data-processing justification. This is the permission layer all over again, one level up.

Escalation quality. An always-on agent with no escalation contract produces its own failure mode: either it interrupts you constantly (and you mute it within a week) or it never does (and you discover in a month that it's been confidently wrong in the background). The gate — what earns a human ping, what must be included in the ping, what happens when no one answers — is now core harness engineering, not a nice-to-have.

Memory discipline. Server-side threads that "expire after short inactivity" and aren't eligible for zero-data-retention or HIPAA workflows are a warning label, not a footnote. Persistence is a compliance surface. Where your daemon's memory lives determines which customers you can ever sell it to.

Wei Kai, who heads the AI research institute at China's CAICT, put the honest timeline on it in the same coverage: agents still need improvement in reliability, contextual memory, and long-horizon tasks, and "there is still some distance to go before large-scale adoption." Right. The direction is settled; the distance is real. Both things are true, and only one of them changes your planning.

What to Do This Week

  1. Nominate one channel. Pick a single place where events accumulate and nobody has time to watch them — an alert channel, a support inbox, a PR queue, a bug chat. Write down three events that should trigger work without anyone asking. That list is the seed of your daemon's trigger spec, and the act of writing it will teach you more than any vendor demo.
  2. Write the escalation contract before the autonomy. Define what earns a human ping, what the ping must contain (evidence, what was tried, confidence, the decision you're being asked to make), and what the agent does when nobody answers. An agent that can act but can't escalate usefully is a liability with a queue.
  3. Split the tiers and meter them separately. Sentinel on the cheap model, specialist on the expensive one, handoff logged every time. Terra's 50.3% Terminal-Bench score is the market telling you the watcher tier doesn't need frontier scores — it needs frontier uptime at commodity prices.
  4. Decide where memory lives, on purpose. If your daemon's context sits in someone else's encrypted memory, you've made a retention decision for every customer you'll ever have. Make it explicitly, in writing, now — retrofitting compliance into a running system is how daemons get killed by legal.

The discipline I laid out in Harness Engineering: The Complete Guide to Agent-First Software Development was mostly about the loop around a task — context, tools, verification, recovery. The frontier of that discipline is now the loop around a week: what the system does between your messages, what it remembers when you're gone, and what it decides you need to see. DeepSeek built theirs inside a company that ships model weights. You can build yours inside yours, this quarter, out of parts that all went generally available in the last thirty days.

The agents that matter next year won't be the ones that give the best answer. They'll be the ones that never logged off.
