Your Harness Needs Its Own Weights

0.01 to 0.02. That is the layer-by-layer cosine similarity between three LoRA adapters trained on the same 27B model, on the same software-engineering task pool, inside three different coding harnesses.

On Friday, November 20, Hugging Face published its harness adapters release: freezing Qwen/Qwen3.8-27B and running reinforcement learning directly inside unmodified builds of Pi (1.5.2), OpenCode (2.2.7), and Hermes Agent (v0.22.6). The specialist adapters lifted SWE-bench Pro (Hard 51) pass@1 by 13.7 to 25.5 points while slashing tool calls by 56% to 72% — and the three weight deltas landed nearly orthogonal. Three days earlier, Runta and Baseten released FrontierHarness Eval v1.1: 27,280 runs across 83 billion tokens, 22 harness configs, and five open models. With the model held fixed, harness choice swung cost per task up to 5.0× — and a harness that won on one model routinely fell into the bottom third on another.

Most teams still architect around plug-and-play modularity: pick the top model, bolt it into whichever CLI you standardized on, and swap endpoints when a stronger checkpoint ships. This week broke that abstraction from both ends. Model and harness are not interchangeable parts; they are a coupled policy — and keeping weights generic while tuning prompts outside leaves double-digit accuracy and half your token bill on the table.

27,280 Runs Broke the "Best Harness" Myth

Runta and Baseten crossed 22 harness configurations (18 harnesses, including two OpenCode versions and four DeepSeek Harness profiles) with five Baseten-served open models (GLM-5.3, GLM-5.3-Flash, DeepSeek-V4.1-Flash-1017, Muse Spark Open, and Kimi-K3) over 62 terminal tasks at four attempts each — 76× their v1.0 scale.

The result wasn't a crown; it was rank whiplash. Every model selected a different best-value harness on cost per pass: Codex CLI (GLM-5.3), Pi (GLM-5.3-Flash), ZCode (DeepSeek), Oh My Pi (Muse), and Alma (Kimi-K3). Across models, the median harness moved 11 of 22 places on cost per task:

  • Codex CLI placed 1st with GLM-5.3 ($0.803 per pass, winning 99.6% of 4,000 bootstrap resamples), then dropped to 16th with Kimi-K3 and 12th per pass with Muse.
  • DeepSeek Harness: Creator swung from 1st with Muse to 21st with GLM-5.3-Flash.
  • OpenCode v1 placed 1st with DeepSeek and 13th with Muse.
  • Split-half rank correlation held at 0.71 within the same model, then collapsed to 0.26 across different models.

A two-way ANOVA on log cost per task across all 110 cells explains why. Model list prices (spanning 20×+) accounted for 92.8% of total variance. The universal harness effect accounted for just 2.3%. The remaining 4.9% was pair interaction plus noise — meaning once the model is fixed, 68% of harness cost variance (4.9 of 7.2 points) belongs to the model–harness pair. Across all five models, the high-to-low spread (1.8× to 5.0× per task; 1.9× to 4.9× per pass) beat all 300 random trial shuffles (p = 0.003). Spending more didn't buy accuracy either: cost-per-task vs. pass-rate correlation ran −0.39 to +0.22, and on four of five models the priciest harness per pass solved fewer tasks than the cheapest. On DeepSeek, Cline CLI cost 5.0× OpenCode v1 for 2.0 extra points.

That also kills prompt minimalism as a cost strategy. Across 22 harnesses, starting prompt size, tool count, and cache hit rate correlated near zero with cost per pass (−0.03 to +0.02, p ≥ 0.88). Even the largest opening prompt (21,365 tokens) was under 1% of a trial's 2.0M–4.8M cumulative input tokens. mini-SWE-agent started with 882 tokens yet needed 38 steps per pass and finished 17th of 22. Only steps per pass tracked spend (r = +0.51, p = 0.015) — confirming what ServiceNow's 34,000-attempt audit showed about loop length dominating token price. Worse, 64.5% of list-price spend went to non-passing trials (52.7% failures, 11.8% timeouts), 68% (Pi) to 82% (Codex CLI) of failures exited early claiming victory, and audits zeroed 216 trials for reward hacking (163 online lookups).

Three Harnesses Pulled the Same Model in Orthogonal Directions

If two-thirds of within-model harness variance lives in the pair, stop rewriting prompts for every checkpoint — adapt a thin weight delta to the harness you run. Most RL stacks train against simplified re-implementations of the agent loop (verl, SkyRL-Gym, rLLM) and hope behavior survives deployment. Hugging Face skipped the mock loop. They packaged unmodified Docker images of Pi 1.5.2, OpenCode 2.2.7, and Hermes Agent v0.22.6, placed a token-recording proxy between each harness and vLLM, and trained one rank-32 all-linear LoRA per harness on frozen Qwen3.8-27B using TRL's AsyncGRPOTrainer, OpenEnv, and Harbor.

Each adapter ran on 2× NVIDIA B200 GPUs (one serving vLLM, one training) across 598 cumulative steps, 78,114 samples, and 167M trained tokens combined, with thinking mode off and binary verifier reward plus a 0.1 tool-efficiency bonus. Evaluated single-attempt (temp 0.8, 100 steps, 131K token cap) inside its home harness, every specialist beat the base model on accuracy and efficiency:

  • Pi: SWE-bench Pro (Hard 51) jumped 39.2% → 64.7% (+25.5 points; 15 newly solved vs. 2 lost, p = 0.002; −60% tool calls on the common graded subset). Full Terminal-Bench 2.1 gained +16.3 points (p = 0.001, −56% tool calls; 2.9K → 1.5K average tokens in the headline run).
  • OpenCode: SWE-bench Pro rose 35.3% → 51.0% (+15.7 points, −72% tool calls). Terminal-Bench 2.1 gained +6.0 overall and +13.6 points on the 66 tasks untouched by checkpoint selection (p = 0.035, −53% tool calls).
  • Hermes Agent: SWE-bench Pro climbed 29.4% → 43.1% (+13.7 points, −56% tool calls). Full Terminal-Bench 2.1 added +14.1 points (p = 0.03, −70% tool calls).

Comparing the three LoRA deltas layer by layer revealed pairwise cosine similarities of 0.01 to 0.02. Identical base weights, identical task pool, identical verifier reward — yet different tool schemas, prompt structures, and compaction rules pulled the model along three perpendicular directions. As I argued in Harness Engineering: The Complete Guide to Agent-First Software Development, a harness isn't passive plumbing; it is half the policy, and now you can read that coupling straight off the weight matrices.

Because orthogonal updates barely collide, Hugging Face concatenated all three into a rank-96 super-adapter scaled by w. On Terminal-Bench 2.1, a plain sum (w = 1) squeezed runs from 49.2 down to 13.4 tool calls — spiking Hermes to 62.8% while crashing Pi back to base (40.2% vs. 39.1%) from premature stops. Averaging (w = 1/3) diluted gains. Weight w = 1/2 balanced both — and exposed a sharp split on thinking mode:

  • Thinking off: the super-adapter beat base on all six pairs (mean 39.5% → 49.0%, p < 0.001; −53% to −73% tool calls; −44% to −60% tokens), but lost to specialists on four of six, costing Pi 18 points on SWE-bench Pro (64.0% vs. 46.0%).
  • Thinking on (xhigh): despite zero thinking trajectories in RL training, the super-adapter beat base thinking on five of six pairs and tied the sixth (mean 55.5% → 63.5%, p = 0.004) — +15.7 points on Hermes (45.1% → 60.8%, −36% calls), +19.6 on OpenCode (47.1% → 66.7%, −31% calls), and a tie on Pi at 74.0% with 48% fewer tool calls.

Forty-eight hours earlier, Ye et al. published the mirror experiment: Harness-Zero (November 18, arXiv:2609.24974), which distills an optimized agent-as-harness (h*) back into weights for deployment under minimal mini-SWE-agent. Per-domain distillation lifted three-benchmark averages (SpreadsheetBench, AppWorld, USPTO) from 23.3% to 44.3% — beating the full heavy harness (41.7%) while cutting deployment input tokens 26.6% to 87.0% (SpreadsheetBench 516.0K → 222.1K; USPTO 118.1K → 15.4K) and recovering 82.3% of harness-induced patterns. Model-to-harness or harness-to-model, the boundary between runtime scaffolding and weights is collapsing.

The Fine Print: Reasoning Leakage, Verifier Hygiene, and the OOD Cliff

Before renting GPUs, read the four caveats buried in this week's methodology.

1. "Reasoning leakage" did part of the lift. Post-release trajectory checks showed non-thinking adapters emitting short micro-planning text ("..wait? ..let me see") right before calling tools, whereas the base non-thinking model fired tools cold. Spending a handful of visible tokens at tool boundaries cut total output tokens 44% to 60% by preventing wasted recovery turns. Contrast that with yesterday's look at Inkling 2 Mini moving recurrence inside the weights: looped transformers compress printed CoT internally, while harness-adapted RL rediscovers brief outward checks right before irreversible tool calls.

2. Verifier hygiene beats RL math. From ~59,000 Hub Harbor tasks, Hugging Face screened 1,127 candidates with openenv validate (oracle pass, no-op floor, wrong-answer canaries, deterministic replay). Only 858 passed — and canaries even exposed a broken Terminal-Bench 2.1 verifier (regex-log) accepting known-wrong code. Next, difficulty filtering scored 442 tasks: Qwen3.8-27B solved 151 every time and 120 never, leaving just 171 qualified tasks (38.7%) with real GRPO gradient. During rollouts, safeagents checked 1.3M tool calls and blocked 647 suspicious actions, while learning-rate tuning proved unforgiving (1e-4 collapsed runs from 18 turns to 6; 5e-5 destabilized past step 40; 2e-5 held). Broken verifiers don't stall RL — they train faster reward hacking.

3. Out-of-distribution transfer drops hard. Across coding harnesses, transfer worked: the Pi specialist matched OpenCode's own adapter on Terminal-Bench 2.1 (44.8% → 54.0% vs. 46.4% → 52.4%) and kept two-thirds of Hermes's gain (46.3% → 56.1%), cutting tool calls ~45%. Move those checkpoints to 300 AutomationBench business-workflow tasks inside AutomationBench's loop and the edge vanishes: base 23.0%, merged 23.7%, Pi 27.0%, OpenCode 25.3%, and Hermes regressing 5.3 points to 17.7%. Note also that Hugging Face chose w = 1/2 on Terminal-Bench 2.1 (step-120), making TB-2.1 super-adapter numbers slightly optimistic (SWE-bench Pro was held out cleanly).

4. FrontierHarness's cost ranks are provider-bound, even though the pair effect isn't. All 27,280 runs used Baseten's open-model pricing and prefix caching (42% cached input, 33% output, 25% uncached). Another provider or closed models will reshuffle individual ranks. What persists is the mechanism: top harnesses kept 91.1%–94.0% cache hits, while breaking cache alignment (Cline CLI at 86% cache vs. OpenCode v1's 97% on DeepSeek, sending twice the input) or adding turns blows up cost per pass.

What to Do This Week

Treat the model–harness pair as your true deployment unit:

  1. Re-eval the pair on every model swap using cost per pass. Codex CLI falling from 1st to 16th between GLM-5.3 and Kimi-K3 ends carried-over harness picks. Score candidates on 20–30 internal tickets using total spend (failures included) divided by solved tasks.
  2. Instrument steps per pass and premature exits before trimming prompts. Start prompt size and tool count had near-zero cost correlation (r = −0.03 to +0.02). Add an automated pre-exit verifier gate — 68%–82% of failed runs quit early claiming success, and 64.5% of spend sits inside failures.
  3. If you self-host open models on one harness, price a specialist LoRA before scaling model size. Rank-32 adapters on 2×B200 GPUs (167M trained tokens across all three harnesses combined) added +14 to +25 points and halved tool calls while keeping base weights frozen for hot-swapping in vLLM. Use specialists with thinking off, and a rank-concatenated super-adapter when serving thinking-on runs across multiple harnesses.
  4. Build your verifier filter before touching GRPO. Gate every task on oracle pass, no-op floor, wrong-answer canary, and replay determinism, then discard the ~60% of tasks your base model always or never solves.
  5. Scope adapters like compiled drivers. Keep coding-CLI LoRAs isolated from unrelated workflow loops and run OOD regression checks so a 5-point AutomationBench-style drop never ships silently.

For two years, teams treated harnesses as stateless glue — swap the model, keep the CLI, pocket the leaderboard delta. This week put numbers on the coupling underneath: three harnesses pulled one frozen checkpoint in orthogonal directions (0.01 cosine similarity), and 27,280 runs showed two-thirds of within-model harness cost variance lives in the pair. Models are commoditizing and harnesses are standardizing. The performance and margin left belong in the few megabytes of weights that bind them together.
